Session Lifecycle

stateDiagram-v2
    [*] --> CheckingSession
    CheckingSession --> LoggedIn: Valid JWT found
    CheckingSession --> LoginScreen: No session

    LoginScreen --> Authenticating: Submit credentials
    Authenticating --> LoggedIn: Success
    Authenticating --> LoginScreen: Error

    LoggedIn --> Refreshing: Token expires
    Refreshing --> LoggedIn: Refresh success
    Refreshing --> LoginScreen: Refresh failed

    LoggedIn --> LoggingOut: User clicks logout
    LoggingOut --> LoginScreen: Session cleared

    Note right of CheckingSession: Checks SecureStore on app start
    Note right of Refreshing: Auto-refresh before expiry

RLS Policies

-- Users can only read their own data
CREATE POLICY "users_select_own"
    ON public.users FOR SELECT
    USING (auth.uid() = id);

-- Users can only insert their own identifications
CREATE POLICY "identifications_insert_own"
    ON public.identifications FOR INSERT
    WITH CHECK (auth.uid() = user_id);

-- Users can only view their own history
CREATE POLICY "identifications_select_own"
    ON public.identifications FOR SELECT
    USING (auth.uid() = user_id);

-- Users can only manage their own favorites
CREATE POLICY "favorites_select_own"
    ON public.favorites FOR SELECT
    USING (auth.uid() = user_id);

Security Rules

  • Never store tokens in AsyncStorage (use expo-secure-store)
  • Never expose service_role key to client
  • Always use RLS on every table
  • Always validate JWT on server-side operations
  • Always use HTTPS in production
  • Always hash sensitive data (passwords handled by Supabase)
